# AgroScan AI — Production Scanner Bug Root Cause Analysis

## Executive Summary
This document provides a forensic root-cause analysis of the critical production scanner anomalies identified in AgroScan AI. Through step-by-step tracing of the complete image-to-prediction pipeline (Frontend Camera/Upload &rarr; `ScanPage.jsx` &rarr; `AnalysisPage.jsx` &rarr; `POST /api/v1/predictions/analyze` &rarr; `LeafValidator` &rarr; `MultiProviderConsensusEngine` &rarr; `AgroScanLocalModelProvider` &rarr; `ResultPage.jsx`), we isolated the actual code defects and implemented targeted, surgical fixes adhering to the absolute non-regression rule.

---

## 1. Confirmed Root Cause: Acceptance of Non-Leaf Images
### Symptom
Any uploaded image (selfies, animals, documents, buildings, bare soil, flowers) appeared to be accepted by the scanner as a valid leaf.

### Technical Mechanisms Identified
1. **Unconditional Pass on Missing OpenCV Shared Libraries (`leaf_validator.py` lines 206–230)**:
   In previous commits attempting to make the validation gate "resilient" to container environments missing `libGL.so.1` (OpenCV headless dependency), an unconditional fallback was introduced:
   ```python
   if cv2 is None:
       is_valid_res = w >= 80 and h >= 80
       return LeafValidationResult(
           is_plant=True,
           is_leaf=True,
           leaf_confidence=0.90,
           image_quality=quality_score,
           usable_for_diagnosis=is_valid_res,
           leaf_visibility=0.85,
           status_code="VALID_LEAF",
           ...
       )
   ```
   Whenever `cv2` failed to load (or was not installed with native system packages on cloud hosts like Render), **any image with dimensions $\ge 80 \times 80$ px was unconditionally certified as a valid leaf with 90% confidence.**

2. **Permissive HSV Color Thresholds when cv2 was Loaded**:
   In the OpenCV path, `lower_foliage` was defined as `np.array([18, 20, 20])` and `upper_foliage = np.array([95, 255, 255])`. In OpenCV HSV color space:
   - Hue 18 is yellow-orange/tan.
   - Hue 95 is cyan-blue.
   - Saturation 20 and Value 20 represent near-monochrome shadows.
   This captured almost the entire spectrum of outdoor and indoor objects (wood, tables, clothing, beige walls, animal fur). Furthermore, if `base_green_foliage >= 0.03` (3%), it added the necrotic lesion mask (`Hue [10, 28]`), making almost every photograph exceed the low `0.49` threshold.

3. **Absence of Pure-Python Architectural Independence**:
   The validation gate lacked a self-contained NumPy/PIL implementation of gradient variance and color indices, causing serverless or stripped runtime environments to default to the bypass.

## 2. Confirmed Root Cause: Repeated & Fabricated Disease Predictions
### Symptom
Different images repeatedly returned the exact same disease result (**Tomato Early Blight** or **Tomato Late Blight**) with identical confidence scores ($\sim 0.88$).

### Technical Mechanisms Identified
1. **Deterministic Header Byte Modulo in `AgroScanLocalModelProvider` (`local_model_provider.py` lines 123–128)**:
   When external disease providers were unconfigured or unreachable, `local_model_provider.py` executed:
   ```python
   hash_seed = sum(image_bytes[:64]) if len(image_bytes) >= 64 else len(image_bytes)
   idx = hash_seed % len(matching_diseases)
   selected = matching_diseases[idx]
   confidence = 0.88 if not is_healthy else 0.94
   ```
   **Why this produced identical answers:**
   Standard JPEG files generated by browser canvas (`canvas.toBlob(..., 'image/jpeg', 0.92)`) or phone cameras begin with fixed JFIF headers, APP0 markers, and identical standard quantization tables. The sum of the first 64 bytes (`image_bytes[:64]`) is almost completely invariant across images from the same camera source. With `matching_diseases` containing Solanaceous crops where indices 0 and 1 were `tomato_late_blight` and `tomato_early_blight`, every JPEG selected Tomato with a fabricated confidence of `0.88`.

2. **Invalid External Provider Credentials in Backend Environment**:
   - In `backend/.env`, `PLANT_ID_API_KEY` was populated with `sk-tyy76a81b0e151b6519403` (a Perenual key format, rather than a Kindwise Plant.id key).
   - Calling `https://api.plant.id/v3/identification` with an invalid key failed with HTTP 401 Unauthorized or timed out.
   - Other external providers (`PLANTNET_API_KEY`, `PLANTIX_API_KEY`, `AGRIO_API_KEY`) were unconfigured (set to `None`).

3. **Silent Fallback to Mock Engine in `MultiProviderConsensusEngine` (`consensus_engine.py` lines 234–240)**:
   When external providers failed, `consensus_engine.py` quietly caught the exception:
   ```python
   local_p = self.providers.get("agroscan_local")
   if local_p:
       fallback_res = await local_p.diagnose(...)
       if fallback_res.status == "success":
           valid_results = [fallback_res]
   ```
   This converted an external API failure directly into a synthetic diagnosis of Tomato Late Blight, masking the failure and manufacturing false consensus.

4. **Hardcoded Fallbacks in Custom Predictor (`ml/inference/predictor.py`)**:
   `CustomMLPredictor.predict` returned a hardcoded Tomato Late Blight dictionary (`confidence_score: 0.942`) whenever the binary model was uncompiled.

## 3. Confirmed Root Cause: Stale Prediction Display & Frontend Mock Route
### Symptom
The frontend displayed old predictions, or reloaded into a Tomato Late Blight report.

### Technical Mechanisms Identified
1. **Mock Redirect on Missing State (`AnalysisPage.jsx` lines 31–36)**:
   ```javascript
   if (!imageFile) {
     setTimeout(() => {
       navigate('/results/pred_001');
     }, 800);
     return;
   }
   ```
   If a user refreshed `/analysis`, accessed the URL directly, or experienced state evaporation during navigation, `AnalysisPage` automatically redirected to `pred_001` (the hardcoded mock Tomato Late Blight result in `mockData.js`).

2. **Absence of Scan Request Transaction IDs & Race Conditions**:
   `AnalysisPage.jsx` dispatched requests without transaction IDs or request abort controllers (`AbortController`). If a previous slow request finished after a new image was uploaded, the older scan overwrote the active state.

3. **Result Page Initialization Bypass (`ResultPage.jsx`)**:
   `ResultPage.jsx` did not inspect `location.state?.prediction` on initial mount. It executed `api.get('/predictions/${scanId}')` which failed with 401 for unauthenticated/guest users, falling back to reading `localStorage.getItem('agroscan_scans_v1')` where older scans were stored.

## 4. Surgical Fix Summary

| Component | Defect | Surgical Fix Applied |
| :--- | :--- | :--- |
| `backend/app/services/leaf_validator.py` | `cv2 is None` bypassed validation; permissive HSV thresholds | Replaced with pure NumPy/PIL mathematical validation (discrete Laplacian variance, Excess Green ExG $\ge 12$, NDI, skin YCbCr, straight-edge grid detection). Works 100% with or without cv2. Standardized English and Marathi rejection messages. |
| `backend/app/services/providers/local_model_provider.py` | `sum(image_bytes[:64])` fabricated Tomato Blight (0.88) | Removed mock fallback. Returns `status="model_unavailable"` in production when model binary is uncompiled. In demo mode, uses full SHA-256 hash across diverse crops. |
| `backend/app/services/consensus_engine.py` | Silent fallback to mock engine when APIs fail; non-isolated cache keys | Removed silent mock fallback. Raises explicit `RuntimeError` on provider failure. Binds image SHA-256, target crop, and provider set to cache keys. Prevents caching conflicting or failed diagnoses. |
| `ml/inference/predictor.py` | Hardcoded Tomato Late Blight (0.942) | Requires compiled model binary; throws descriptive error if weights are missing. |
| `backend/app/api/v1/endpoints/scan.py` | Only English error returned on rejection; provider failure treated as 500 | Propagates localized rejection message (`message_mr` for Marathi users, `message_en` for English). Catches `RuntimeError` as HTTP 503 Service Unavailable. |
| `frontend/src/pages/AnalysisPage.jsx` | Redirected to `pred_001`; no request cancellation | Replaced `pred_001` redirect with `/scan`. Added unique transaction ID (`scanRequestId`), `AbortController` cancellation, and stale-response guards. |
| `frontend/src/pages/ResultPage.jsx` | Ignored `location.state.prediction`, risked reading stale localStorage | Initializes state directly from `location.state?.prediction` when `id === scanId`. Strictly isolates scan ID. |
| `frontend/src/i18n/en.js` & `mr.js` | Missing standard rejection translation strings | Added standard English and Marathi rejection messages. |
